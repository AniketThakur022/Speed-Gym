The content graph, and what it can actually teach

Every node type and every relationship in the live database — then the mechanism that turns them into an adaptive solve-along session, and the one measurement that decides how adaptive it can really be today.

The whole graph

Seven node types in three functional bands. The middle band is the spine — everything else either orders it, attaches to it, or hangs teaching material off it.

Skill — mastery vocabulary Problem — what a learner answers SolveAlong — the walkthrough Explainer — concept card Trap — known misconception Sutra — classical rule Book — provenance

Three edge families, three different jobs

The most expensive mistakes in this project came from treating one of these as another. Each is now pinned to a single job, with an explicit prohibition attached.

Ordering

REQUIRES · 255 edges · Skill → Skill

Genuine prerequisite structure: you need this before that. Deepest real chain is 6 hops (Division back to Arithmetic). This is what "what should I learn first" reads.

NeverOnly 40 of 422 skills have any prerequisite, so for 90% of the vocabulary this question returns nothing at all.

Attachment

PREREQUISITE_OF · 2,439 edges · Skill → Problem

The Q-matrix: which skills a given problem exercises. Bipartite and depth-1 — it says a problem needs a skill, never that one skill needs another. This is the join that attributes an answer to a mastery score.

NeverDo not walk it transitively. Its name invites exactly that misreading, and the architecture document made it.

Adjacency

FRONTIER_OF 2,486 · NEXT_TOPIC 82

Similarity and browse order. FRONTIER_OF is 100% reciprocal — every edge has its mirror — so it expresses "related to", not "comes before". Useful for suggesting a sibling when a topic runs dry.

NeverNEXT_TOPIC was inverted into prerequisites once and asserted every sub-topic as its own root's prerequisite. Retracted — it cut the longest chain from 23 hops to 6.

How an adaptive solve-along session is built

The engine runs entirely on the learner's device. Nothing below needs a network call — which is why the graph has to carry the structure rather than a server deciding in the moment.

01

Read where the learner stands

Mastery is a probability per skill, held on device. Each problem carries a pinned mastery_key naming which skill its result updates — pinned deliberately, because the old behaviour picked a key by sorting a problem's skill parents alphabetically, so renaming any skill could silently move the mastery of problems it had nothing to do with.

P(L) per skill · 4 bands: fractured <35% · fragile <70% · fluid <90% · mastered
02

Compose the session — 60 / 20 / 20

Sixty percent on the current focus, twenty on skills that were known and are decaying, twenty on the frontier — the next thing whose prerequisites are already satisfied. The frontier is where the REQUIRES DAG earns its place: a skill is only offered once everything it requires is fluid.

primary 60% · sinking 20% (spaced repetition) · frontier 20% (prerequisites met)
03

Pick problems through the Q-matrix

For each chosen skill, walk its Skill→Problem edges, filter to what is servable — verified answer, trust tier permitting, no known defect — and rank by difficulty against the learner's level. Quarantined content is excluded and counted, so an empty page is explainable rather than mysterious.

(:Skill {name})-[:PREREQUISITE_OF]->(:Problem) → filter → rank by difficulty
04

Choose the render mode from the mastery band — this is the adaptive part

The same problem is presented three different ways depending on how well the learner knows the skill. Fractured gets guided: the walkthrough leads, step by step. Fragile gets solve-along: the learner works, the steps stay available. Fluid gets quick: just the problem, timed. The content is identical; the scaffolding is what adapts.

fractured → guided fragile → solve_along fluid → quick
05

Serve the walkthrough from the paired SolveAlong

Every problem has ordered steps, each with an operation, a result and a description. The chatbot's hint ladder is built from exactly these steps minus the final one, which is how it can be genuinely helpful and still structurally incapable of handing over the answer.

791 SolveAlongs · hint level N = step N · final step withheld
06

Score, update, and decide what comes next

A wrong answer is matched against the problem's known traps, so the feedback names the actual misconception rather than saying "incorrect". Mastery updates on the pinned key, the result feeds the spaced-repetition schedule, and the next session's 60/20/20 is computed from the new state.

answer → trap match → BKT update on mastery_key → schedule → next session

How adaptive it can actually be, measured

The mechanism above is built and tested. Its resolution — how finely it can tell one learner apart from another — is set by how the 794 servable problems distribute across mastery keys. They distribute badly.

Three keys hold three quarters of the content

Arithmetic carries 296 problems. Algebra carries 200. Basic Operations carries 103. Because mastery is one probability per key, the engine tracks a single number across all 296 Arithmetic problems — so a learner who is fluent at addition but lost at percentages reads as one blended score, and the session composer cannot tell those two learners apart. At the other end, 77 keys hold exactly one problem, where a mastery estimate rests on a single answer and a lucky guess looks identical to competence.

This is not an engine defect — the psychometrics reproduce their pre-loss behaviour exactly, and the render-mode ladder works. It is a vocabulary granularity problem in the graph: the middle is missing. And it compounds with the ordering gap — only 40 of 422 skills have any prerequisite, so the frontier band of the session has nothing to reason about for 90% of the vocabulary.

Highest leverage

Split the three giant keys

Breaking Arithmetic, Algebra and Basic Operations into real sub-skills converts 75% of the pool from one blended score into something the engine can actually steer by.

Ordering

Extend REQUIRES beyond 40 skills

The frontier band is only as good as the DAG. Each new prerequisite edge makes one more skill answerable to "what comes next".

Volume

Give the singleton keys more problems

77 skills cannot support a mastery estimate on one item each. The factory generates verified problems per pattern — this is exactly what it is for.

Unblocks both

Decide the serving path

The 25-book corpus holds thousands of keyed exam questions with no route to a learner. Binding it is the single largest source of both new problems and finer skills.
